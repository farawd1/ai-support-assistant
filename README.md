# Support

Локальный интерфейс оператора с реальным AI-анализом. Python 3.12+, FastAPI, SQLite, Jev и DeepSeek.

## Запуск Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
# Заполнить локальный .env по .env.example
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/. Ключи находятся только в `.env`, исключённом из Git. В браузер они не передаются.

## Обработка

- Новое обращение сохраняется в SQLite со временем поступления и становится в очередь. Четыре фоновых обработчика выполняют реальные вызовы провайдеров. Прерванная обработка возобновляется после запуска сервера.
- DeepSeek самостоятельно выделяет каталог тем из исходного набора. Для каждого обращения выбирает подходящую тему или предлагает новую с описанием и точной цитатой сообщения. Если каталог изменился во время создания новой темы, модель проверяет её повторно. Названия нормализуются для предотвращения точных дубликатов. Семантическую уникальность оценивает модель; это не математическая гарантия.
- Jev оценивает риск безопасности, потери денег и блокировки основного действия. Прозрачные правила превращают оценки в приоритеты P0/P1/P2. Порог 0.65 пока не калиброван на размеченной выборке.
- DeepSeek формирует черновик или уточняющий вопрос. Каталог тем не является источником бизнес-правил. У приложения нет доступа к заказам, платежам или политикам компании, и модель получает запрет выдумывать их.
- Только действия оператора изменяют счётчики рассмотренных обращений. Принятие ответа сохраняет решение локально, сообщение клиенту не отправляется.
- Ошибки API отображаются явно. Нет деморежима, шаблонной генерации, автоматической подмены провайдеров или фиктивной статистики.

## Происхождение данных

160 ранее сгенерированных сообщений сохранены как синтетические входные данные. У них нет достоверного времени поступления (`received_at = NULL`). Вымышленные даты, черновики и решения операторов удалены из рабочей базы. Исходная база до миграции сохранена локально в `data/before-live-v2.db`, исключена из Git и не используется приложением. Сообщения, созданные пользователем, сохранены отдельно как `source=manual`.

История обработки использует реальные `analyzed_at` и `reviewed_at`, а не дату генерации примеров. Средняя задержка измеряет реальный вызов анализа, включая синтетический вход. Статистика не доказывает качество классификации. Каталог показывает темы, описания и примеры связанных обращений.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

В тестах API подменяются только изолированными фикстурами; рабочий сервис всегда использует подключённые модели. Проверяются очередь, повторный анализ, сохранение действий, миграция, цитаты, новые темы и отсутствие подмены при ошибках.

Локальная однопользовательская версия без авторизации. Привязка сервера к 127.0.0.1 обязательна. Нет почтового, CRM или мессенджерного канала; обращения добавляются через форму.

## Автооператор

Переключатель в шапке включает или отключает автоматические решения для всех готовых необработанных и новых обращений. По умолчанию выключен; выбор сохраняется в SQLite после перезапуска.

Отдельный запрос DeepSeek проверяет черновик и выбирает принятие, уточнение, эскалацию или ручную проверку с причиной. Оценка уверенности модели ниже 0.9 и необходимость внешней операции оставляют решение человеку. P0/P1 и эскалация исходного анализа принудительно направляются специалисту. Уверенность является самооценкой модели, а не измеренной точностью.

Принятие сохраняет ответ в локальном обращении. Уточнение не закрывает обращение; эскалация остаётся в очереди. Подключения к отправке клиенту и платёжным операциям нет. Отдельные счётчики показывают действия агента, не увеличивая число решений человека. Любое ручное решение имеет приоритет над параллельным AI-запросом. Отключение блокирует применение запросов, начатых до переключения. История сохраняет автора, причину и фактическое время. Ошибки можно повторить отдельно.
