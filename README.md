# Repl.io

Локальный интерфейс оператора с реальным AI-анализом. Python 3.12+, FastAPI, SQLite локально / PostgreSQL на Vercel, Jev и DeepSeek.

## Запуск Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
# Заполнить локальный .env по .env.example
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/. Ключи находятся только в `.env`, исключённом из Git. В браузер они не передаются.

## Обработка

- Новое обращение сохраняется в SQLite со временем поступления и становится в очередь. Четыре фоновых обработчика выполняют реальные вызовы провайдеров. Прерванная обработка возобновляется после запуска сервера.
- DeepSeek самостоятельно выделяет каталог тем из исходного набора. Для каждого обращения выбирает подходящую тему или предлагает новую с описанием и точной цитатой сообщения. Если каталог изменился во время создания новой темы, модель проверяет её повторно. Названия нормализуются для предотвращения точных дубликатов. Семантическую уникальность оценивает модель; это не математическая гарантия.
- Jev оценивает риск безопасности, потери денег и блокировки основного действия. Прозрачные правила превращают оценки в приоритеты P0/P1/P2. Порог 0.65 пока не калиброван на размеченной выборке.
- DeepSeek формирует черновик или уточняющий вопрос. Каталог тем не является источником бизнес-правил. У приложения нет доступа к заказам, платежам или политикам компании, и модель получает запрет выдумывать их.
- Только действия оператора изменяют счётчики рассмотренных обращений. Принятие ответа сохраняет решение локально, сообщение клиенту не отправляется.
- Ошибки API отображаются явно. Нет деморежима, шаблонной генерации, автоматической подмены провайдеров или фиктивной статистики.

## Происхождение данных

160 ранее сгенерированных сообщений сохранены как синтетические входные данные. У них нет достоверного времени поступления (`received_at = NULL`). Вымышленные даты, черновики и решения операторов удалены из рабочей базы. Исходная база до миграции сохранена локально в `data/before-live-v2.db`, исключена из Git и не используется приложением. Сообщения, созданные пользователем, сохранены отдельно как `source=manual`.

История обработки использует реальные `analyzed_at` и `reviewed_at`, а не дату генерации примеров. Средняя задержка измеряет реальный вызов анализа, включая синтетический вход. Статистика не доказывает качество классификации. Каталог показывает темы, описания и примеры связанных обращений.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

В тестах API подменяются только изолированными фикстурами; рабочий сервис всегда использует подключённые модели. Проверяются очередь, повторный анализ, сохранение действий, миграция, цитаты, новые темы и отсутствие подмены при ошибках.

Аккаунты имеют роли пользователя и оператора. Нет почтового, CRM или мессенджерного канала; обращения добавляются пользователями через форму.

## Автооператор

Переключатель в шапке включает или отключает автоматические решения для всех готовых необработанных и новых обращений. По умолчанию выключен; выбор сохраняется в SQLite после перезапуска.

Отдельный запрос DeepSeek проверяет черновик и выбирает принятие, уточнение, эскалацию или ручную проверку с причиной. Оценка уверенности модели ниже 0.9 и необходимость внешней операции оставляют решение человеку. P0/P1 и эскалация исходного анализа принудительно направляются специалисту. Уверенность является самооценкой модели, а не измеренной точностью.

Принятие сохраняет ответ в локальном обращении. Уточнение не закрывает обращение; эскалация остаётся в очереди. Подключения к отправке клиенту и платёжным операциям нет. Отдельные счётчики показывают действия агента, не увеличивая число решений человека. Любое ручное решение имеет приоритет над параллельным AI-запросом. Отключение блокирует применение запросов, начатых до переключения. История сохраняет автора, причину и фактическое время. Ошибки можно повторить отдельно.

## Вход и права

Создать аккаунты на сервере (пароли вводятся скрыто, от 12 символов):

```sh
python -m app.accounts customer user
python -m app.accounts operator operator
```

Открытой регистрации и выбора роли при входе нет. Пользователь видит только «Отправить запрос» и получает номер принятого запроса. Оператор имеет обзор, обращения, темы, автооператора и аудит; создавать запросы ему запрещает сервер. Старые обращения сохраняются без владельца.

Пароли хешируются PBKDF2-SHA256 с солью и 600 000 итерациями. Сессии живут 12 часов, хранятся в базе в виде хешей, cookie имеет HttpOnly и SameSite=Strict. Выход аннулирует сессию. После пяти неудачных попыток аккаунт временно блокируется на пять минут в текущем процессе. Для публичного развёртывания нужны HTTPS, COOKIE_SECURE=true и ограничение запросов на уровне прокси. Локальный SQLite требует постоянного диска. На Vercel приложение использует внешний PostgreSQL через DATABASE_URL.

## Аудит

Оператор выбирает начало и окончание в своём часовом поясе. Сервер принимает даты с часовым поясом и фильтрует по диапазону [начало, окончание). Результаты доступны постранично, по 100 событий. Записываются входы, выходы, успешные команды пользователей и операторов, создание запросов, результаты AI-анализа и решения оператора и автооператора. Пароли, ключи и тексты сообщений в аудит команд не попадают. Запись начинается с обновления; исторические события входа не восстанавливаются. История старых решений остаётся в карточках обращений. Аудит доступен только операторам, интерфейса редактирования/удаления событий нет.

## Публикация на Vercel

Проект использует FastAPI entrypoint `app.main:app` и отдельный приватный подписчик `queue_tasks` для Vercel Queues. Локальные четыре обработчика остаются только для локального сервера. В облаке новые запросы, повторный анализ и автооператор запускаются сообщениями очереди; payload содержит только тип задачи и ID обращения. База хранит текст, состояния, аккаунты, сессии и аудит независимо от жизни функций. Временная SQLite в `/tmp` не используется.

1. Импортировать GitHub-репозиторий в Vercel (framework FastAPI, root ./).
2. Подключить Neon PostgreSQL через Storage / Marketplace. Проверить `DATABASE_URL` для production. Для preview использовать отдельную базу/ветку.
3. Добавить `TYPESAFE_API_KEY`, `DEEPSEEK_API_KEY`, `COOKIE_SECURE=true` и четыре `BOOTSTRAP_*` переменные с именами и случайными паролями двух аккаунтов. Пароли от 12 символов. Ключи и пароли не добавлять в Git.
4. Опубликовать проект. Инициализация PostgreSQL сериализована блокировкой; SQLite-данные не переносятся автоматически. Начальные аккаунты создаются только если имя ещё не существует; изменение env не меняет пароль существующего аккаунта. После создания аккаунтов удалить `BOOTSTRAP_*_PASSWORD` из настроек.
5. Проверить вход обеих ролей, отправку запроса, работу очереди и аудит. Готовые настройки сами по себе не подтверждают успешное развёртывание.

Прерывание функции не сбрасывает чужую обработку: каждый анализ получает токен попытки, а устаревшая попытка не может перезаписать результат. Активная обработка защищена 6-минутным сроком; отдельный запуск ограничен 240 секундами. Дубли завершённой задачи не вызывают AI повторно. Если публикация в очередь не удалась, запись остаётся в БД, а оператор может нажать «Восстановить очередь». Очередь и функции имеют лимиты и тарификацию Vercel.
